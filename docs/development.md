# Development

## Workflow

Development is organized into small, incremental sessions.

Each session should:

- Have a clear objective.
- Produce a functional result.
- End with a commit.
- Update documentation when required.

## Git

- Default branch: `main`
- Commit style: Conventional Commits

## Development Principles

- Keep it simple.
- Document only what matters.
- Describe the current state, not assumptions.
- Implement only what is needed.
- One responsibility per component.
- Functionality comes before polish.

## Documentation

Documentation evolves together with the project.

- Architectural decisions belong in `architecture.md`.
- Development conventions belong in `development.md`.
- Project progress belongs in `roadmap.md`.
- Session history belongs in `docs/sessions/`.
